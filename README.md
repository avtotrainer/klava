# KLAVA — კლავიატურის ტრენაჟორი

**KLAVA** არის Python-სა და Tkinter-ზე შექმნილი საგანმანათლებლო კლავიატურის ტრენაჟორი, განკუთვნილი ძირითადად 7–12 წლის ქართულენოვანი მოსწავლეებისთვის.

პროექტის მიზანია კლავიატურაზე ასო-კლავიშების მდებარეობის ათვისება, სწორი ბეჭდვის ჩვევის ჩამოყალიბება და მოსწავლის შედეგებზე დაფუძნებული ადაპტიური სწავლების განვითარება.

**ძირითადი პრინციპი:**

კარგი მუშაობა → ნაკლები სამუშაო, მაგრამ იგივე პასუხისმგებლობა.

## 1. საგანმანათლებლო პრინციპები

KLAVA-ს პროდუქტის სპეციფიკაცია ეფუძნება შემდეგ მოთხოვნებს:

- სიზუსტე სიჩქარეზე მნიშვნელოვანია.
- შეცდომიანი სიჩქარე არ ჯილდოვდება.
- მინიმალური დავალება შედგება ორი სტრიქონისგან (`MIN_LINES = 2`).
- ადაპტიური დატვირთვის დონეებია `100 → 50 → 20 → 4`.
- Progress bar წარმოადგენს სასწავლო უკუკავშირის მექანიზმს.
- კარგი შედეგი ამცირებს დავალების მოცულობას, მაგრამ არა ხარისხის მოთხოვნებს.

**შენიშვნა:** ყველა ჩამოთვლილი პედაგოგიური მექანიზმი ჯერ არ არის სრულად განხორციელებული. იხილეთ პროექტის მიმდინარე სტატუსი.

## 2. პროგრამის მიმდინარე შესაძლებლობები

პროგრამის მიმდინარე კოდში წარმოდგენილია:

- Tkinter-ზე აგებული გრაფიკული ინტერფეისი.
- ეკრანზე გამოსახული QWERTY კლავიატურა.
- თითების შესაბამისი ფერადი აღნიშვნები.
- ტექსტის სტრიქონების მიხედვით აკრეფა.
- სწორი და არასწორი კლავიშის ვიზუალური უკუკავშირი.
- დავალების მინიმალური მოცულობის შემოწმება.
- კონფიგურირებადი Fullscreen/Kiosk რეჟიმი.
- ქართული და ინგლისური ინტერფეისის რესურსები.
- პროგრამის პარამეტრები `config.ini` ფაილში.

კლავიშების შესასწავლად გამოიყენება ინგლისური ანბანის დიდი ასოები, ფიზიკურ კლავიატურასთან შესაბამისობის გასამარტივებლად.

## 3. არქიტექტურა

პროექტის ძირითადი სტრუქტურაა:

```text
klava/
├── main.py
├── trainer.py
├── config.ini
├── logic/
├── ui/
├── exercises/
├── data/
├── resources/
├── docs/
├── flake.nix
├── README.md
└── CHANGELOG.md
```

ძირითადი პასუხისმგებლობები:

| კომპონენტი | დანიშნულება |
|---|---|
| `main.py` | პროგრამის შესვლის წერტილი |
| `trainer.py` | სასწავლო სესიის მართვა და კომპონენტების კოორდინაცია |
| `logic/` | ბეჭდვის ლოგიკა, პროგრესი, კონფიგურაცია და რესურსების დამუშავება |
| `ui/` | ინტერფეისისა და კლავიატურის ვიზუალური მართვა |
| `exercises/` | სავარჯიშოების სასიცოცხლო ციკლი და კლავიშების მოვლენების დამუშავება |
| `data/` | სავარჯიშო ტექსტები |
| `resources/` | ლოკალიზაცია, გაფორმება და კლავიატურის მოდელის მონაცემები |
| `docs/` | ტექნიკური და საგანმანათლებლო დოკუმენტაცია |

არქიტექტურული მიზანია გამოთვლითი ლოგიკისა და ვიზუალური ინტერფეისის მკაფიო გამიჯვნა.

**მიმდინარე შეზღუდვა:** ყველა არსებული მოდული ჯერ არ არის სრულად ინტეგრირებული ძირითად შესრულების ნაკადში. არქიტექტურული შესაბამისობა შემდგომი განვითარების ერთ-ერთი ამოცანაა.

## 4. გაშვება

საჭიროა Python 3.10 ან ახალი ვერსია და Tkinter-ის მხარდაჭერა.

რეპოზიტორიის ძირითად კატალოგში გაუშვით:

```bash
python main.py
```

Nix-ის მომხმარებლებისთვის, მხარდაჭერილ `x86_64-linux` გარემოში:

```bash
nix develop
python main.py
```

Nix-ის განვითარების გარემო განსაზღვრულია `flake.nix` ფაილში.

პროგრამის გაშვების შემდეგ სავარჯიშო იწყება მენიუდან.

## 5. კონფიგურაცია

ძირითადი კონფიგურაცია მდებარეობს ფაილში:

`config.ini`

იგი შეიცავს:

- ფანჯრისა და Kiosk რეჟიმის პარამეტრებს.
- ინტერფეისის ენას.
- სავარჯიშოების ფაილის მდებარეობას.
- მინიმალური სტრიქონების რაოდენობას.
- დაგეგმილ Quality Gate-ის ზღვრებს.
- ბეჭდვის ქცევის კონტროლის პარამეტრებს.
- ვიზუალური გაფორმების პარამეტრებს.

კონფიგურაციის პარამეტრის არსებობა არ ნიშნავს, რომ შესაბამისი ფუნქცია უკვე ჩართულია.

## 6. Kiosk რეჟიმი

სავარჯიშოს დროს პროგრამას შეუძლია ჩართოს Fullscreen რეჟიმი, დამალოს მაუსის კურსორი და შეზღუდოს ფანჯრის ჩვეულებრივი დახურვა.

ადმინისტრაციული დასრულების კომბინაცია ნაგულისხმევად არის:

`Ctrl + Alt + Shift + Q`

მისი შეცვლა შესაძლებელია `config.ini`-ში.

Kiosk რეჟიმი არის აპლიკაციის დონეზე მოქმედი შეზღუდვა და არა ოპერაციული სისტემის უსაფრთხოების მექანიზმი. სისტემური კლავიშების ყველა კომბინაციის დაბლოკვა გარანტირებული არ არის.

## 7. ხარისხის კრიტერიუმები

პროექტის დამტკიცებული სასწავლო მოთხოვნებია:

| კრიტერიუმი | მნიშვნელობა |
|---|---|
| Accuracy | ≥ 97% |
| CPM | ≥ 180 |
| Success Streak | 3 ზედიზედ წარმატება |
| Minimum Lines | 2 |
| Adaptive Levels | 100 → 50 → 20 → 4 |

**მიმდინარე მდგომარეობა:** Accuracy-ის, CPM-ისა და წარმატებების სერიის სრული შეფასების მექანიზმი ჯერ არ არის გააქტიურებული ძირითად სასწავლო პროცესში.

ეს პარამეტრები წარმოადგენს პროდუქტის მოთხოვნებს და არა უკვე დასრულებული ფუნქციონალის დადასტურებას.

- ტექნიკური დოკუმენტაცია საჭიროებს მოქმედ კოდთან საბოლოო შეთანხმებას.

## 10. ტესტირება და შემოწმება

განვითარების გარემოში (მაგალითად, `nix develop`-ის შემდეგ) გაუშვით:

```bash
python -m compileall -q main.py trainer.py logic ui exercises tests
ruff check .
python -m pytest -q
```

CI შემოწმება განსაზღვრულია `.github/workflows/validate.yml`-ში. `pytest` მოიცავს ლოგიკისა და სავარჯიშოს ფეიკ-UI ტესტებს; ის **არ ადასტურებს** რეალური GUI-ის, Kiosk რეჟიმის ან პედაგოგიური Quality Gate-ის სრულ გამართულობას.
