# `main.py` — გაშვება და ერთი ეგზემპლარის შეზღუდვა

**თარიღი:** 2026-10-29 · **შტო:** `fix/single-instance` · **სტატუსი:** PR #19 გაერთიანებულია `main`-ში; გამოქვეყნებულია `v0.3.2-beta.1` რელიზში.

## პრობლემა და მიზეზი

მომხმარებელმა Windows-ის KLAVA-ში აღმოაჩინა განმეორებითი გაშვებით მრავალი ფანჯრის გახსნა. საწყის `main.main()`-ში `tk.Tk()` იქმნებოდა ყოველგვარი პროცესთაშორისი შემოწმების გარეშე. შესწორება შესულია `v0.3.2-beta.1` გამოცემაში.

## პასუხისმგებლობები

- `main.main()` იღებს ბლოკირებას GUI-სა და მომხმარებლის მონაცემების ინიციალიზაციამდე.
- `logic/single_instance.py::single_instance()` მართავს მხოლოდ ოპერაციული სისტემის ბლოკირებას; არ იცნობს Tkinter-ს, სასწავლო შეფასებას ან UI-ს.
- `main._run_app()` ინარჩუნებს არსებულ ინიციალიზაციას, ფაილის მომზადებასა და `mainloop()`-ს.
- `Trainer` რჩება სესიის კოორდინატორად; სასწავლო წესები არ შეცვლილა.

ცალკე მოდული საჭიროა სისტემური ბლოკირების GUI-სგან გამოსაყოფად და რეალურ პროცესებში დამოუკიდებლად შესამოწმებლად.

## შესრულება და შედეგი

1. შეყვანა: გაშვების არგუმენტები და მომხმარებლის სავარჯიშოების დირექტორია `library_dir()`.
2. ჩვეულებრივი გაშვება ხსნის `%LOCALAPPDATA%/KLAVA/instance.lock`-ს (არარსებული `LOCALAPPDATA`-სას პროექტის არსებული fallback არის `~/AppData/Local/KLAVA`).
3. Windows-ში `msvcrt.locking(..., LK_NBLCK, 1)` იღებს პირველი ბაიტის ბლოკირებას; POSIX-ში გამოიყენება არამომლოდინე `fcntl.flock`.
4. დაკავებული ბლოკირებისას პროცესი სრულდება GUI-ს შექმნისა და სავარჯიშოების შეცვლის გარეშე. პირველი ფანჯარა მუშაობას აგრძელებს; წინ წამოწევა ამ ცვლილების ნაწილი არ არის.
5. წარმატებისას ბლოკირება ინახება მთელი `mainloop()`-ის განმავლობაში. ჩვეულებრივი დასრულება, გამონაკლისი ან პროცესის იძულებითი შეწყვეტა ათავისუფლებს მას.
6. ფაილურ სისტემასთან მოულოდნელი შეცდომა აჩვენებს გაშვების შეცდომას; დაუცველი რეჟიმით პროგრამა არ იწყება.

შეზღუდვა ვრცელდება **ერთი მომხმარებლის მონაცემების დირექტორიაზე**, დამოუკიდებლად პროგრამის საქაღალდისა და მიმდინარე სამუშაო დირექტორიისა. სხვა მომხმარებლის დამოუკიდებელ პროფილს საკუთარი KLAVA შეუძლია გაუშვას. განზრახ განსხვავებული `LOCALAPPDATA` სხვადასხვა ბლოკირების სივრცეს ქმნის.

`--edit-exercises` გამონაკლისია: არსებული მალსახმობი ხსნის Notepad-ს და არ იწყებს მეორე სასწავლო სესიას. იგი ხელმისაწვდომი რჩება KLAVA-ს მუშაობის დროსაც.

## შესრულებული შემოწმება

```bash
python -m compileall -q main.py trainer.py logic ui exercises scripts tests
python scripts/check_resource_links.py
```

ახალი ტესტები ამოწმებს რეალური პროცესების კონკურენციას, სხვა სამუშაო საქაღალდიდან გაშვებას, ავარიულ შეწყვეტას, გამონაკლისის შემდეგ გათავისუფლებას, დამოუკიდებელ პროფილებს, GUI-მდე უარყოფას და რედაქტორის შენარჩუნებას.

ლოკალურად: 51 ტესტი წარმატებულია; 1 რეალური Tk GUI ტესტი გამოტოვებულია ეკრანის არარსებობის გამო. Ruff, სინტაქსი და რესურსების ბმულები შემოწმებულია. Windows-ის არსებული PR CI ასრულებს ამავე ტესტებსა და ინსტალატორის შემოწმებას. `scripts/test_windows_installer.ps1::Test-Launch` დამატებით ამოწმებს აწყობილი EXE-ს მეორე გაშვების დასრულებას, პირველის შენარჩუნებასა და ზუსტად ერთ ფანჯარას. მისი საბოლოო შედეგი ჩაიწერება PR-ში.

გარემოს მომზადებისას სისტემურ `/usr/bin/python3`-ს Tkinter არ ჰქონდა; სამუშაო Python-ს ჰქონდა. `apt-get`-ით Xvfb-ის დამატება გარემოს უფლებებით ვერ შესრულდა. რეალური GUI შემოწმება Windows CI-ზეა დატოვებული; ლოკალური GUI წარმატება არ არის განცხადებული.

## მიღების შემოწმება და შეზღუდვები

Windows-ზე ახალი ინსტალატორით გაშვების შემდეგ მალსახმობზე განმეორებითი დაჭერისას მხოლოდ პირველი ფანჯარა უნდა დარჩეს. დახურვის ან Task Manager-ით შეწყვეტის შემდეგ ხელახლა გაშვება კვლავ უნდა მუშაობდეს. ფიზიკურ სასკოლო კომპიუტერზე ეს მიღების შემოწმება ჯერ არ შესრულებულა.

PyInstaller-ის onefile ფორმატს შეიძლება ჰქონდეს bootloader და შიდა პროცესი; მოთხოვნა არის ერთი **სასწავლო ფანჯარა/სესია**, არა Task Manager-ში აუცილებლად ერთი ჩანაწერი. მეორე გაშვებისას ამოღების დროებითი პროცესი შესაძლოა მოკლედ გამოჩნდეს.

## უსაფრთხოება და უკუქცევა

`instance.lock` დარჩება დისკზე და ეს ნორმალურია: მდგომარეობას განსაზღვრავს OS-ის ბლოკირება და არა ფაილის არსებობა. მოქმედი პროგრამის დროს მისი წაშლა დაუშვებელია — სხვადასხვა ფაილის ბლოკირებამ შეიძლება ორი ეგზემპლარი დაუშვას. PID-ის ან მხოლოდ ფაილის არსებობის შემოწმება არ გამოყენებულა: ავარიამ ძველი ჩანაწერი შეიძლება დატოვოს.

სავარჯიშოები არ იშლება და ადმინისტრატორის უფლება არ მოითხოვება მომხმარებლის საკუთარ დირექტორიაში. უკუქცევა შესაძლებელია ცვლილების commit-ის revert-ით და ხელახლა აწყობით; ეს აღადგენს მრავალჯერადი გაშვების ძველ ქცევას. `main`-ში გაერთიანება და ახალი გამოშვება ცალკე ნებართვას მოითხოვს. კანონიკური ჩანაწერი GitHub-შია; Drive/Slack ასლები არ შექმნილა.
