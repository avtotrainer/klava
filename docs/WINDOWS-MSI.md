# KLAVA — MSI (Windows Installer)

## მიზანი

MSI გამოიყენება სკოლაში IT ადმინისტრატორის მიერ KLAVA-ს ცენტრალიზებული ინსტალაციისათვის. არსებული Inno Setup EXE ინსტალატორი უცვლელია და რჩება ჩვეულებრივი მომხმარებლის (Current User / All Users) არჩევანისთვის.

## არქიტექტურა

- `packaging/windows-msi.wxs` — WiX Toolset v6, x64, **perMachine** პაკეტი.
- `KLAVA-x64.msi` — MSI პროდუქტია; ინსტალაცია ადმინისტრატორის უფლებებს მოითხოვს. ჩვეულებრივი მომხმარებლისათვის უპირატესია EXE-ის Current User რეჟიმი.
- პროგრამის ფაილები თავსდება `%ProgramFiles%\KLAVA MSI`-ში. ეს განსხვავებული კატალოგია, რათა დამოუკიდებელი Inno Setup და MSI დეინსტალატორები ერთმანეთს ფაილებს არ წაუშლიდნენ.
- მონაცემები / სავარჯიშოთა პირადი ბიბლიოთეკა მუშაობს `%LOCALAPPDATA%\KLAVA`-ში. MSI პაკეტი ამ დირექტორიას არც ქმნის და არც შლის.
- საწყისი `default-exercises.klv` ინსტალირდება პროგრამის გვერდით; იგი **არ არის** მომხმარებლის მონაცემების წასაშლელი ფაილი.
- `MajorUpgrade` ემსახურება ამავე MSI პროდუქტის მომავალ განახლებებს. MSI და EXE ერთმანეთის ავტომატური განახლების მექანიზმები **არ არის**.

## აწყობა და შემოწმება

GitHub Actions `Windows MSI` workflow: ბრენდინგის შექმნა → PyInstaller EXE → pinned WiX 6.0.2 → MSI build → ჩუმი `msiexec /i` → ორ ფაილზე შემოწმება → `msiexec /x` → payload-ის მოცილების შემოწმება → artifact upload.

დისტრიბუციის დაწყებამდე CI-ის რეალური წარმატებული შედეგი აუცილებელია. ინსტალატორი ციფრულად ხელმოწერილი არ არის; ორგანიზაციული Windows პოლიტიკა შეიძლება დამატებით ნებართვას ითხოვდეს.

**შეზღუდვები:** ჯერ არ ჩატარებულა GPO/Intune deployment, არ არის დადასტურებული ხელმოწერა ან MSI-ის მრავალვერსიული upgrade ტესტი. არსებული EXE ინსტალაციის MSI-ით ავტომატური შეცვლა არ ხდება.

## Start მენიუში მოძებნა

MSI ინსტალაცია ქმნის ყველასათვის ხელმისაწვდომ მალსახმობს `Start > All apps > KLAVA > KLAVA` (`%ProgramData%/Microsoft/Windows/Start Menu/Programs/KLAVA/KLAVA.lnk`). MSI დეინსტალაციისას მალსახმობიც იშლება. 2026-10-29-ის წინანდელ MSI-პაკეტს მალსახმობი არ ჰქონდა; ამ მიზეზით პროგრამა Programs and Features-ში ჩანდა, მაგრამ Start ძიებაში შეიძლება არ გამოჩენილიყო. შესწორება ცალკე PR-შია, საბოლოო CI შედეგამდე ვერ ჩაითვლება დადასტურებულად.

## EXE/MSI ერთდროული ინსტალაციისგან დაცვა (PR #16)

Inno Setup (`AppId=KLAVA.CurrentUser`) ქმნის `KLAVA.CurrentUser_is1` ჩანაწერს Windows-ის Uninstall რეესტრში. WiX MSI ამოწმებს HKLM/HKCU uninstall ჩანაწერს და ახალი MSI ინსტალაციისას შეტყობინებით წყვეტს ოპერაციას, თუ EXE უკვე დარეგისტრირებულია. არსებული EXE **ავტომატურად არ იშლება**, რათა არ დაიკარგოს მომხმარებლის ცვლილებები. პირადი `.klv` სავარჯიშოები ინახება `%LOCALAPPDATA%\KLAVA`-ში და არც ერთი ინსტალატორის მონაცემების გასუფთავებას არ ექვემდებარება.

**შეზღუდვა:** ეს დაცვა ერთმხრივია (EXE → MSI) და HKCU-ში მიმდინარე მომხმარებლის ჩანაწერს ხედავს; სხვა მომხმარებლის პირადი EXE ინსტალაციის აღმოჩენა MSI სისტემურ რეჟიმში გარანტირებული არ არის. MSI-ის დაყენების შემდეგ EXE-ის ცალკე გაშვებით კვლავ შესაძლებელია მეორე პაკეტის დამატება, სანამ საპირისპირო შემოწმება არ განხორციელდება. სრული საერთო პროდუქტის მიგრაცია ჯერ არ განხორციელებულა.

2026-10-29: EXE ინსტალატორს დაემატა MSI-ს მიერ შექმნილი `HKLM64\Software\KLAVA\MSI` მარკერის შემოწმებაც (`InitializeSetup`), ამიტომ მეორე პაკეტის დაყენება ორივე მიმართულებით იბლოკება, თუ შესაბამისი რეგისტრაციის ჩანაწერები ხელმისაწვდომია. მარკერი მიბმულია MSI Start Menu კომპონენტზე და მისი წაშლა ხდება MSI-ის დეინსტალაციისას. ძველად უკვე ერთდროულად დაყენებულ ორ ეგზემპლარს ეს ცვლილება ავტომატურად არ ასუფთავებს. საბოლოო Windows CI შედეგი და რეალურ კომპიუტერზე სცენარები ჯერ დასადასტურებელია.
