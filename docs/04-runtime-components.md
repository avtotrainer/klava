# მოქმედი მოდულები: logic → ui → exercises → data/resources

ეს მიმოხილვა აგრძელებს [`main.py`](01-main.md)-სა და [`Trainer`](03-trainer.md)-ის აღწერას. ყოველი კომპონენტისათვის გამიჯნულია რეალური პასუხისმგებლობა და ჯერ განუხორციელებელი მოთხოვნა.

## 1. `logic/` — გამოთვლითი და რესურსების ფენა

| კლასი / მოდული | Does | Does not | Inputs | Outputs |
|---|---|---|---|---|
| `TypingEngine` — `logic/engine.py` | ადარებს სიმბოლოს სამიზნეს; ითვლის პოზიციას; მართავს შეცდომის შემდეგ დაბლოკვის მდგომარეობას; `lock_duration`-ის მითითებისას დაბლოკვა დროის გასვლის შემდეგ თავისით იხსნება (ნაგულისხმევად `None` — ხანგრძლივობა მფლობელის დასამტკიცებელია) | არ ხატავს UI-ს; არ არის მიერთებული Trainer-ის მიმდინარე სესიაზე | სტრიქონი, აკრეფილი სიმბოლო, guard-ის პარამეტრები | `bool` სწორი დაჭერისთვის, `finished`, `state` |
| `Progress` — `logic/progress.py` | ითვლის სწორ ნაბიჯებზე დაფუძნებულ პროცენტს | არ ზომავს Accuracy-ს ან CPM-ს | `total`, `step()`, `reset()` | `percent` |
| `Config` — `logic/config.py` | კითხულობს `config.ini`-ს | არ წყვეტს სასწავლო შედეგს | INI ფაილი, სექცია, გასაღები | ტექსტი, მთელი რიცხვი ან boolean |
| `Resources` — `logic/resources.py` | კითხულობს თარგმანებს, თემებს, კლავიატურის JSON მოდელს | არ ხატავს და არ აფასებს ბეჭდვას | რესურსების მდებარეობა, ენა, თემა | კონფიგურაცია, ტექსტი, მოდელი |

**ცნობილი შეუსაბამობა:** `TypingEngine`-ისა და `Progress`-ის არსებობა არ ნიშნავს, რომ ისინი სესიის შესრულების ნაკადში გამოიყენება.

## 2. `ui/` — ვიზუალური ფენა

| კლასი | Does | Does not | Inputs | Outputs |
|---|---|---|---|---|
| `Canvas` — `ui/canvas.py` | ხატავს ტექსტს, სტატუსსა და ეკრანის ელემენტებს | არ წყვეტს კლავიშის სისწორეს | `root`, ვიზუალური მონაცემები, თემა | Tkinter Canvas ობიექტები |
| `Keyboard` — `ui/keyboard.py` | ხატავს კლავიშებს და ცვლის მათ ფერებს | არ ადგენს წარმატების სასწავლო კრიტერიუმებს | Canvas, ზომები, კლავიატურის მოდელი და ფერები | კლავიშის ვიზუალური მდგომარეობა |
| `AppMenu` — `ui/menu.py` | აჩვენებს მენიუს და იძახებს გადაცემულ callback-ებს | არ მართავს შეფასების ალგორითმს | `root`, callbacks, ტექსტის რესურსები | მენიუს მოქმედებები |

## 3. `exercises/` — სავარჯიშოები

| კლასი | Does | Does not | Inputs | Outputs |
|---|---|---|---|---|
| `Exercise` — `exercises/base.py` | განსაზღვრავს `start`, `stop`, `on_key` და `finished` კონტრაქტს | არ ქმნის კონკრეტულ სავარჯიშოს | ქვეკლასის იმპლემენტაცია | საერთო ინტერფეისი |
| `TypingExercise` — `exercises/typing.py` | ამუშავებს ერთი სტრიქონის კლავიშებს, პოზიციას და UI-ის უკუკავშირს | ჯერ არ ითვლის CPM/Accuracy-ს | UI, Keyboard, ტექსტი, Tkinter event | მიმდინარე მიზანი, დასრულების სტატუსი |

## 4. `data/` და `resources/`

- `data/sentences.txt` — სასწავლო ტექსტი; იკითხება `Trainer._load_sentences` მეთოდით.
- `resources/i18n/` — ქართული/ინგლისური ინტერფეისის ტექსტები.
- `resources/themes/` — ვიზუალური თემის მონაცემები.
- `resources/keyboard/fingers.json` — თითების ჯგუფებისა და ფერების მონაცემები.

## ალგორითმების აღწერის შაბლონი

**Goal → Inputs → Steps → Output → Educational rationale**

მაგალითი — `TypingExercise`:

1. **Goal:** ბავშვმა სწორად აკრიფოს სტრიქონი.
2. **Inputs:** სიმბოლოების სტრიქონი და დაჭერილი კლავიში.
3. **Steps:** მიმდინარე სამიზნის წაკითხვა → შედარება → სწორზე პოზიციის გაზრდა / არასწორზე ვიზუალური უკუკავშირი.
4. **Output:** დასრულების სტატუსი და კლავიატურის/ტექსტის ვიზუალური ცვლილება.
5. **Educational rationale:** შეცდომიანი დაჭერა არ უნდა ითვლებოდეს დასრულებულ სამუშაოდ.

## Known limitations

საჭიროა პასუხისმგებლობების შემდგომი გამიჯვნა ისე, რომ `TypingExercise`-ის არსებული ქცევა არ შეიცვალოს ტესტირების გარეშე. სასწავლო Quality Gate და ადაპტიური დატვირთვა შემდგომი სამუშაოა.
